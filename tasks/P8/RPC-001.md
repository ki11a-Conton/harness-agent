# TASK: RPC-001

## Goal

Create the transport-agnostic RPC gateway package `packages/gateway` per AGENT_ARCHITECTURE_PLAN v2.0 §84 (RPC), §156 (Cancellation), §161 (Remote Security).

## Why

The agent runtime needs a stable, host-facing method surface (`session.*`, `agent.list`, `tool.list`, `skill.list`, `trace.get`) that clients (desktop/CLI/HTTP) can bind to without owning the loop, tool execution, permission logic, or session persistence (§85). Streaming stays on structured `AgentEvent`s (§84).

## Dependencies

- `@ar/contracts`, `@ar/core`, `@ar/session`, `@ar/security` (runtime deps)
- `@ar/model` (dev only, test fakes)
- Root `tsconfig.json` reference

## Preconditions

`AgentRuntime` (`packages/core/src/runtime/runtime.ts`) exposes `createSession`/`startTurn`/`runTurn`/`getAgent`; `SessionService` wraps resume; `InMemoryApprovalStore` provides one-shot approval resolution with expiry semantics.

## Contracts

### RpcMethodRegistry

- `register(name, handler)` — duplicate name throws
- `invoke(name, params, ctx): Promise<unknown>` — unknown method throws `AgentError` with `INTERNAL_ERROR` and `cause.jsonrpcCode = -32601` (JSON-RPC "Method not found" semantics); handler errors are normalized to structured `{ code, message }` (via `toRpcError`/`rpcErrorBody`), never a raw stack
- `has`, `listMethods`

### createRuntimeRpc methods (§84)

- `session.create` (agentId, cwd → Session; unknown agent → error)
- `session.send` (sessionId, text → { turnId })
- `session.run` (sessionId, turnId → TurnOutcome; caller `ctx.signal` is linked to the run; concurrent duplicate run → error)
- `session.cancel` (sessionId, turnId → { sessionId, turnId, status: "cancelled" | "not_running" }; aborts the registered run and awaits its outcome — §156 cancellation propagation)
- `session.resume` (sessionId → Session)
- `session.approve` (approvalId, value: "allow" | "deny", decidedBy? → ApprovalDecision; binding via InMemoryApprovalStore: one-shot, unknown id → structured error, `allow` past `expiresAt` resolves `expired` — §161 approval binding)
- `session.subscribe` (sessionId, afterSequence? → event snapshot; true streaming is `EventStore.stream` wrapped by the caller)
- `agent.list` (safe projection: id/name/description/mode — no systemPrompt over the wire, §161)
- `tool.list`, `skill.list` (host-wired providers; absent provider → structured error)
- `trace.get` (sessionId → events list)

### InMemoryTransport

- `InMemoryTransport.pair()` → client/server endpoints with async (microtask) message delivery
- Server side: `connect(RpcServer)`; client side: `request(method, params, ctx?)` resolving to result, rejecting with structured `AgentError`
- Carries `RpcContext` (incl. `signal`) to the server — cancellation works end-to-end

## Security Invariants

- Errors crossing the boundary expose only `{ code, message }`; stacks stay server-side (§161 audit)
- `agent.list` returns a projection, not full definitions
- Approvals are one-shot and session-bound in the store (`cancelAll(sessionId)`, per-session listing)
- This package never touches tool execution/permission logic directly — it calls `AgentRuntime.runTurn`, which routes through ToolOrchestrator/PermissionEngine/SandboxManager

## Tests

- session.create→send→run full chain
- cancel aborts a blocked turn (store status + events)
- caller AbortSignal through transport cancels the run
- approve allow / deny / expired / unknown
- agent.list / tool.list / skill.list
- trace.get, subscribe snapshot with afterSequence
- unknown method, duplicate register, raw handler error → structured
- concurrent runs on one runtime: cancel one, other unaffected
