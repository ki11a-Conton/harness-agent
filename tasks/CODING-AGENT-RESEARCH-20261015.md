# Coding agent 提示词与配套机制研究

用户要求：实际阅读 Hermes、Codex、Claude Code 快照、pi、DeepSeek Harness、ZCode 的提示词及其上下文、工具、记忆、缓存实现，按七类 coding 能力提出适合当前 Harness 的优化。Aider 作为代码检索和编辑修复的补充参考。

## 范围与边界

- 基线 Harness `2a141309f01acae3707060faf1fab8aa247ed31d`；独立研究分支，不修改原工作区未提交文件。
- 本轮交付源码对比、可复算本地探针、优化方案与验收计划；不把方案写成已实现，不自动切换默认提示词、不发布新版本。
- 保持 Runtime freeze；策略改善走 challenger → 同条件 paired eval。确实的基础设施缺陷另以反例修复。
- 原生 Git/HTTP 获取源码，不使用 GitHub 连接器；不引入子 agent。
- 引用固定版本、区分官方源码与聚合快照。无明确许可证的 Claude Code 快照仅研究设计，不复制实现或大段提示词。

## 做什么、怎么做、怎么验收

1. 固定参考版本，记录实际阅读文件及 SHA-256，形成可离线核查的来源清单。
2. 对比实际工具表、提示词加载、检索、压缩、记忆、缓存观测及测试，避免把已有能力重新列成缺失。
3. 使用基线生产 provider 和本地 HTTP/SSE 服务验证缓存统计；不替换 fetch，不调用付费模型。给出真实观察、已知缺口及未知项。
4. 给出分阶段实施计划，每项写明做什么、怎么做、验收、依赖、来源及尚未实施状态。附候选提示词设计，不启用它。
5. 运行探针、来源复核、相关既有回归、文档门禁；报告范围和限制，不以离线桩证明模型能力或真实缓存命中率。
