# Web 日常交互审查任务

用户要求：模拟正常用户在 Web 端日常点击和输入，复现并修复 UI 组件交互问题；
只有在未发现问题时才转向其他 agent 优化。最新远端 main 基线为
`b6a865287dac2133053e2c6bca1d4580e40fbcf2`，在独立 worktree 工作。

做什么：扩展已有 30 场景验收，检查可见按钮、菜单、表单、键盘与移动布局，
重点覆盖原交付矩阵尚未逐控件验收的日常行为。原 146 行是审查条目，不能作为
已经完成的交互数量；不可达、未实现、禁用项分别记录，不冒充通过。

怎么做：真实 Chromium 加载真实生产 Web/HTTP/WebSocket；本地 loopback 模型
仅产生可控文本/工具/等待状态，实际文件读写、审批、问答和会话状态仍走生产
Orchestrator/Permission/Sandbox。不拦截或伪造 RPC 成功，不通过直接调用 RPC
代替用户按钮操作；可读取响应、持久化日志和实际文件作为结果证据。桌面及
390/320 窄屏、中文/英文、刷新/断线/重启按场景覆盖，检查焦点和草稿所有权。

问题先保存原始浏览器操作、错误、截图、RPC 和固定源码；再加入确定性反例，
修正最小必要的宿主适配或受控 UI 衍生模块。保持上游原始包和许可，衍生模块
必须可重建并通过现有 provenance 门禁。Core 架构冻结，禁止绕过执行边界。

怎么验收：每个已测行为都有输入动作、预期 UI、真实后端/持久化结果和状态。
未预期的 console/pageerror、失败 RPC、外网访问、焦点丢失、草稿串会话、无效
点击都需审查。修复项须原版失败、修正版通过，并复验相邻流程和已有完整
30 场景；随后类型、相关单元/集成/安全、完整 clean 测试、实际浏览器和最终
main CI 验收。保存失败原件，不靠重跑、跳过或削弱断言消除失败。

边界：不调用付费模型，不使用 GitHub 连接器或子 agent，不发布 release。
不对真实用户目录做破坏性测试，所有删除/改写仅在拥有的临时测试工作区。
