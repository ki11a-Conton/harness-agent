# TASK: CTX-001

## Status

In Progress（主会话待验收）

## Goal

Implement `HierarchicalInstructionDiscovery` in `packages/context` (`@ar/context`): hierarchical AGENTS.md discovery with `root → nested → cwd` precedence per AGENT_ARCHITECTURE_PLAN v2.0 §34, §111, §184 (build order `13 context`).

## Why

Instructions are hierarchically scoped: a repository-root AGENTS.md applies everywhere, nested subdirectory AGENTS.md files refine it, and the cwd-level document is the most specific (§34). This is the scoped-guidance model the runtime adopts; without discovery, the loop cannot load project contracts (L2), local directory contracts (L3) or the cwd document at all. A size budget must be enforced and truncation reported so a pathological AGENTS.md cannot poison context silently (§34: "But enforce a size budget and report truncation").

## Dependencies

- CONTRACT-001 — `DiscoveredInstruction` / `InstructionDiscovery` / `InstructionDiscoveryOptions` in `packages/contracts/src/context.ts` (P3 extension section for CTX-001/002/003). Interface-level only; no dependency on other P3 tasks (parallelizable).

## Scope

### Create

- `packages/context/src/discovery.ts` — `HierarchicalInstructionDiscovery implements InstructionDiscovery`:
  - `discover(cwd, opts?)` → `Promise<DiscoveredInstruction[]>`: walks the filesystem relative to `cwd`
  - precedence per §111 acceptance: the repository-root `AGENTS.md` first with `scope: "root"`; subdirectory `AGENTS.md` files with `scope: "nested"` ordered by ascending depth; the cwd document itself last with `scope: "cwd"`

  - defaults `maxBytesPerFile: 50_000` (50 KiB) and `maxDocuments: 4`; a document over the byte budget is truncated at the last whole-line boundary, gets a trailing marker line `# [truncated ...]`, and is returned with `truncated: true`
  - does not follow symbolic links; a single file that fails to read is skipped (the document is omitted, discovery continues)
  - no AGENTS.md found → empty array

## Key Design Decisions

- **root → nested → cwd is an ordering contract** — the returned array positions the root document first, nested documents in ascending depth order, and the cwd document last (most specific wins by position), exactly matching §111 acceptance "correct precedence".
- **documents expose provenance** — every `DiscoveredInstruction` carries `path` (source path), `scope`, and `sizeBytes` per §111 "Must expose source path / scope / size", so callers can render provenance and users can audit which AGENTS.md governs a directory.
- **truncation is explicit, not silent** — content beyond `maxBytesPerFile` is cut at a line boundary and receives the `# [truncated ...]` marker plus `truncated: true`; the flag is the "warn on truncation" surface (§111) at the data level, no separate logging channel (see Residual Risks).
- **vendor/generated directories are excluded by name** — `node_modules`, `.git`, `dist` never contribute nested instructions.
- **symlinks are never followed** — avoids cycles and duplicate documents; a symlinked AGENTS.md is simply absent from results (see Residual Risks).
- **read failures degrade to a partial result** — one unreadable document is skipped and the rest are still returned; discovery never aborts on a single file.

## Tests

- Root precedence: `cwd` under a repo root → root document present with `scope: "root"` in first position
- Nested depth ordering: root → `a/AGENTS.md` → `a/b/AGENTS.md` → cwd document, ascending depth, cwd last
- `cwd == root` dedup: when `cwd` is the repository root, the root document appears exactly once (not duplicated as both root and cwd)
- `maxDocuments` cap honored (with the default of 4)
- Truncation: oversized file → cut at a line boundary, `# [truncated ...]` marker present, `truncated: true`, `sizeBytes` reflects the source file
- Directory skipping: AGENTS.md inside `node_modules` / `.git` / `dist` is not discovered
- No AGENTS.md anywhere on the path → empty array

## Residual Risks

- **Symbolic links are not followed** — in monorepo/symlinked layouts a linked AGENTS.md is skipped and its scoped instructions are missed; a recorded, deliberate deviation (monorepo support is not a P3 requirement).
- **Truncation is byte-counted but line-aligned** — the budget is checked against lines split on `\n`, so multi-byte UTF-8 is safe (cuts always land on line boundaries), but a single very long line can exceed `maxBytesPerFile` and is kept whole once started.
- **Read failures are silent** — a skipped unreadable document produces no log surface or warning; callers only see the absence of a document. Acceptable at this phase; surface via diagnostics in a later task if needed.
