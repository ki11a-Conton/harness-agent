# TASK: CTX-003

## Status

In Progress（主会话待验收）

## Goal

Implement `DefaultCompactor` in `packages/context` (`@ar/context`): context compaction — fold compressible blocks into one structured summary block while preserving goal / constraints / active failures / pending approvals / important decisions and the security policy byte-for-byte — per AGENT_ARCHITECTURE_PLAN v2.0 §38, §113, §184 (build order `14 compaction`).

## Why

A long agent session grows beyond any token budget; §38 mandates "detect overflow → select compressible blocks → generate structured summary → validate summary → replace old blocks → preserve active task state", and §113's acceptance is a 100k+ token synthetic session that compacts and continues the task. The never-compact guarantees (§38: security policy, pending approval, active task objective, known failing test, uncommitted important decision) must survive so compaction never weakens policy or loses task state — without this, the loop cannot resume any long-lived task within budget.

## Dependencies

- CONTRACT-001 — `CompactionSummary` / `NEVER_COMPACT_SOURCES` / `Compactor` and `ContextBlock` fields in the P3 extension section of `packages/contracts/src/context.ts`. No dependency on CTX-001 / CTX-002 (pure contract-level, parallelizable).

## Scope

### Create

- `packages/context/src/compaction.ts` — `DefaultCompactor implements Compactor`; pure, synchronous:
  - `compact(blocks, summary)` → `ContextBlock[]`
  - never-compact if: source in `NEVER_COMPACT_SOURCES` (`system`/`user`), or (`trust: "trusted"` and source not in `{tool, web, memory, subagent}`), or `compressible: false`; every other block is compactible and folded
  - all compactible blocks collapse into a single summary block: `id: "compaction-summary"`, `source: "memory"`, `trust: "semi-trusted"`, `tokens: Math.ceil(content.length / 4)`, `compressible: false` (the summary is never re-compacted), high `priority: 900` so it survives later budget passes
  - markdown rendering: `# Compaction Summary` header; `goal` renders under `## Goal`; each of constraints / decisions / filesChanged / commandsRun / tests / failures / openTasks / importantFacts renders as a `## <Section>` bullet list only when non-empty
  - no compactible block → return the input array unchanged (no summary block)
  - preserved blocks keep their original relative order; the summary block is appended after the last preserved block so leading system/user context (goal, security policy) is never displaced
- `packages/context/src/compaction.test.ts` — tests below

### Modify

- `packages/context/src/index.ts` — re-export `DefaultCompactor` (aggregate export of the `@ar/context` surface)

### Forbidden

- No folding of never-compact blocks (byte-for-byte preservation)
- No I/O, no async, no shared state during compaction
- No cross-package imports beyond `@ar/contracts`

## Key Design Decisions

- **never-compact predicate is the security fence** — `NEVER_COMPACT_SOURCES` (system/user), trusted blocks outside the ephemeral source allowlist `{tool, web, memory, subagent}`, and `compressible: false` all opt out; security policy, pending approvals and caller-marked critical blocks survive byte-for-byte. Trusted but ephemeral traffic (tool/web/memory/subagent) may fold when the block is marked compressible.
- **single summary block, semi-trusted** — the summary is `source: "memory"`, `trust: "semi-trusted"`: derived content that must never be promoted into system policy (§33 "untrusted content must never be promoted"), `compressible: false` so it cannot fold again, and `priority: 900` so a later CTX-002 budget pass keeps it over ordinary traffic.
- **"preserve" means structure plus raw survival** — §113's required fields (goal, constraints, active failures, pending approvals, important decisions) map onto `CompactionSummary` fields: the caller supplies the values (it is the contract author of what is important), the compactor renders only non-empty fields, and the never-compact predicate additionally guarantees the raw content of protected blocks survives untouched.
- **no-op on nothing to fold** — when zero blocks are compactible the input is returned as-is; compaction must never rearrange or duplicate context.
- **ordering preserves origin** — preserved blocks keep their relative order and the summary block is appended last, so system/user ledges (goal, security policy) stay in front.
- **skill digests are not folded twice** — skill documents are already folded into digests by the loader before blocks reach the compactor, so the compactor does not special-case skills and never re-folds a digest (a digest arrives as a single block whose source/compressible flags are decided by the loader). The plan does not specify skill folding, but double-folding is avoided by design; if the existing loader contradicts this, the contracts remain the authority and this assumption is recorded here.

## Tests

- Folding: N compactible blocks → exactly one `compaction-summary` block; preserved blocks unchanged
- Non-compressible preserved byte-for-byte: never-compact and `compressible: false` blocks keep identical content and fields
- Markdown field rendering: goal + every non-empty list section render; empty fields produce no section
- Empty summary: a fully empty summary renders only the `# Compaction Summary` header
- No compactible input: returned as-is (same order, no summary block)
- 100k+ synthetic scenario: 30 × 4000-token compactible blocks + 5 non-compactible blocks → ≤ 6 blocks total, all 5 protected blocks preserved, all 30 folded into the single summary (the §113 "100k+ synthetic session → compact → continue task" setup at unit level)
- Determinism: same (blocks, summary) → same preserved blocks and summary content; the summary block `timestamp` is `Date.now()` and is excluded from equality

## Acceptance Criteria

From plan §113 (verbatim): "Compaction."; Acceptance: `100k+ synthetic session → compact → continue task`; Must preserve `goal`, `constraints`, `active failures`, `pending approvals`, `important decisions`.

From plan §38 (verbatim): "Never compact away: `security policy`, `pending approval`, `active task objective`, `known failing test`, `uncommitted important decision`" — enforced by the never-compact predicate; the synthetic 100k+ fold keeps every protected block byte-for-byte.

## Residual Risks

- **Summary persistence is deferred** — wiring the summary into snapshot/restore is SESSION-001-style integration for a later phase; LOOP callers must keep the summary block in the blocks list across turns (the compactor only returns the new array).
- **char/4 token estimate** — `Math.ceil(content.length / 4)` is a heuristic, not a tokenizer; misestimation shifts later CTX-002 budget planning, not correctness of preservation.
- **Skill digest double-folding** — if a shipped loader ever emits multi-block skill content, the allowlist predicate could fold it; contracts remain the authority and this doc's assumption (loader folds first) must be revisited in that case.
- **Summary timestamp** — `Date.now()` on the summary block makes run-to-run byte equality of the summary impossible; determinism holds for selection and content, not the timestamp field.
