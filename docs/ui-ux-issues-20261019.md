## 1. 主界面不应出现「插件」入口

- **类别**：界面精简
- **优先级**：P1
- **现象**：左侧栏存在「插件」菜单项，点击后进入插件管理页面（安装、启用、配置插件）。
- **期望**：Harness Agent 面向最终用户，不暴露插件管理概念。侧栏不再出现该入口。
- **验收标准**：
  - 侧栏菜单中不存在「插件」项；
  - 全站 UI 文案中不再出现「插件」二字（含设置页内的相关导航项，见第 4 条）；
  - 插件系统本身可以继续存在于后端，只是不再对用户暴露。

## 2. 自定义模型 API 应支持选择推理等级

- **类别**：功能缺失
- **优先级**：P1
- **现象**：设置 → 模型 → 自定义模型 API，填入 URL 与 API Key 后能成功拉取上游模型列表，但**无法选择推理等级（reasoning effort）**，只能在 `config` 里手改。
- **期望**：对齐 <https://github.com/deepseek-ai/deepseek-harness>，在模型选择处即可自由切换推理等级（如 Default / Low / Medium / High），无需改配置文件。
- **验收标准**：
  - 自定义 provider 的每个模型，若能提供推理等级，则在模型选择器中显示对应档位；
  - 切换后立即生效，且该选择按会话持久化；
  - 上游不支持推理等级的模型，明确显示为无档位，而不是报错。

## 3. 删除设置里的「Agent 预设」

- **类别**：界面精简
- **优先级**：P2
- **现象**：设置中存在「Agent 预设」导航项。
- **期望**：本项目没有 Agent 预设这一概念，删除该导航项与其页面。
- **验收标准**：设置导航中不存在「Agent 预设」；相关入口（含设置内的跳转链接）一并清理。

## 4. 删除设置里的「内置插件」

- **类别**：界面精简
- **优先级**：P2
- **现象**：设置中存在「内置插件」导航项，展示内置插件列表与运行状态。
- **期望**：删除该导航项与其页面。
- **验收标准**：设置导航中不存在「内置插件」；不残留指向它的链接或提示文案。

## 5. 删除通用设置里的「当前版本」

- **类别**：界面精简
- **优先级**：P3
- **现象**：设置 → 通用设置中显示「当前版本：x.y.z」一行。
- **期望**：删除该行。
- **验收标准**：通用设置页面不再显示版本号行；更新检查等其它功能不受影响。

## 6. 删除右下角「编码状态」按钮

- **类别**：界面精简 / 美观
- **优先级**：P2
- **现象**：界面右下角固定悬浮一个「编码状态」按钮，视觉上突兀，且用途不明。
- **期望**：删除该悬浮按钮及其弹窗。
- **验收标准**：界面上不再存在该按钮；不因删除而留下布局空洞或报错。

## 7. 删除主界面正中的「探索未至之境」

- **类别**：界面精简
- **优先级**：P2
- **现象**：新建会话时，对话区正中显示大标题「探索未至之境」。
- **期望**：删除该标题，空会话保持简洁。
- **验收标准**：空会话不再渲染该文案；输入框位置与布局保持正常。

## 8. 调用模型报 `finish_reason` 错误（缺陷）

- **类别**：缺陷
- **优先级**：**P0**
- **现象**：正常对话调用模型时，出现错误并中断本轮：
  ```
  OpenAI chat completion ended without a normal finish_reason (finish_reason: length)
  ```
- **影响**：直接导致对话不可用，是本次反馈中唯一阻断性问题。
- **分析方向**（供实现者参考，非结论）：
  - `finish_reason: length` 表示上游因**输出长度上限**而截断，这是 OpenAI 协议中合法且常见的终止原因，不应被当作协议错误；
  - 当前实现对非 `stop` / `tool_calls` 的 `finish_reason` 一律判定为异常终止，把「被截断」与「协议损坏」混为一谈；
  - 需区分：`length`（截断，可继续/可提示）、`content_filter`（内容过滤）、其它未知值（协议异常）。
- **期望**：`finish_reason: length` 时正常收尾本轮，向用户提示「输出已达长度上限」，并允许继续。
- **验收标准**：
  - 上游返回 `finish_reason: length` 时，不抛错误、不中断会话；
  - UI 给出可理解的提示（如「回复被长度限制截断」）；
  - 未知/异常 `finish_reason` 仍按错误处理，不放松校验；
  - 补充对应回归测试。

## 9. 对话框左下角缺少权限模式选择器

- **类别**：功能对齐
- **优先级**：P1
- **现象**：当前只能在别处（或配置）设置权限，对话输入区左下角没有常驻的权限档位选择。
- **期望**：对齐 deepseek-harness，在对话框左下角提供三档选择：
  - **仅可查看**（只读）
  - **工作区修改**（可写工作区）
  - **完全权限**（不受限）
- **验收标准**：
  - 输入框左下角常驻显示当前档位，可点开切换；
  - 切换后对新动作立即生效；
  - 切到「完全权限」时有明确的二次确认提示；
  - 档位状态与会话绑定并在界面上可见。

## 10. 缺少目标模式与计划模式

- **类别**：功能对齐
- **优先级**：P2
- **现象**：当前没有 deepseek-harness 的「目标模式」与「计划模式」。
- **期望**：引入两种模式：
  - **目标模式**：把一个长期目标交给 Agent，跨多轮持续推进，可暂停/恢复/编辑；
  - **计划模式**：先产出计划供人确认，确认后再执行。
- **验收标准**：
  - 输入区可切换模式，当前模式可见；
  - 目标模式支持设定、暂停、恢复、编辑、清除；
  - 计划模式在计划未确认前不执行副作用操作。

## 11. 上下文自动压缩对齐 Codex

- **类别**：能力对齐
- **优先级**：P2
- **现象**：当前上下文压缩策略不如 Codex 的自动压缩好用。
- **期望**：参考 Codex 的自动压缩机制（接近上限时自动折叠早期上下文并保留关键结论），做到用户无感、不丢关键信息。
- **验收标准**：
  - 长会话接近上下文上限时自动触发，无需手动操作；
  - 压缩后仍能准确引用此前的关键结论与文件路径；
  - 压缩过程在 UI 上可见（有提示），但不打断对话；
  - 提供手动触发入口作为兜底。

## 建议实施顺序

1. **第 8 条（P0 缺陷）** — 唯一阻断性问题，优先修复。
2. **第 1、2、9 条（P1）** — 直接影响核心体验：去掉插件入口、能选推理等级、能选权限档位。
3. **第 3、4、6、7、10、11 条（P2）** — 界面精简与能力对齐。
4. **第 5 条（P3）** — 纯展示项，最后处理。

- 第 1、3、4、5、6、7 条都是「做减法」，可以合并为一个「面向最终用户的界面精简」改动一次性交付。
- 第 2、9、10、11 条是「做加法 / 对齐」，建议按能力拆分独立改动，便于分别验证。
- 本清单只描述**现象与期望**，具体落点在实现时由维护者定位。
