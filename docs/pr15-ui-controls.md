# PR #15：Web 编程交互

原始反馈保留在 [十一项问题](ui-ux-issues-20261019.md)，实施和验收计划见根目录 `plan(20261019-114023).md`。

更新源码后请重新构建并重启 Web 宿主，使前后端使用同一版资源。进程固定已校验的启动图，运行中直接替换其前端文件会被拒绝。

输入框左下角提供三档会话权限：仅可查看、工作区内修改、完全权限。工作区模式保留原配置的审批要求；完全权限必须勾选风险确认，执行仍经过原工具权限、沙箱和资源预算。只读和未确认计划也约束已有子任务，不改冻结的 Agent 定义。收紧权限会撤销正在等待的工具调用。停止已拥有的终端资源保留原来的审批、沙箱和归属校验，避免限制模式把资源困住。

权限切换期间显示“正在保存权限”，当前档位跟随已提交的状态；保存失败会显示原因。计划审阅、目标状态和整理完成等更新会在持久化后推送到界面，已有会话记录继续保留。

“编程 / 计划 / 目标”选择器管理当前任务模式：

- 计划模式允许读取和规划，拒绝项目写入、命令和有副作用的委派。模型给出计划后可以展开审阅，再点击“批准并实施”。批准不会提升只读权限。批准执行使用持久请求 ID，重试不会重复入队。
- 目标模式保存目标，复用原生 inbox 与 SessionActor 跨轮执行；可以编辑、暂停、恢复、清除。默认最多 10 轮，可通过 `goals/edit` 把上限调整到 1–100。界面显示轮次和受阻原因。只有原 Verification 的 `verified_complete` 或人工明确完成才能把目标标为完成；未验证且达到预算时进入受阻状态。暂停阻止后续派发，正在结束的回合保留真实结果；需要立即中断时使用原停止按钮。
- 宿主重启后从持久目标和原 inbox 恢复，不补造第二条 prompt。无活动目标时不扫描会话或反复读取元数据。

自定义 API 的推理档位属于具体模型。在“模型选项”中声明该模型实际支持的档位及协议值，例如：

```json
{"low":"low","medium":"medium","high":"high"}
```

声明后原生模型选择器显示对应档位，选择会持久到本会话，并进入下一次真实 OpenAI-compatible 请求的 `reasoning_effort`。不支持请留空或设为 `false`，界面会明确提示没有推理档位；未声明、非法档位都不会被猜测或发送给上游。推理档位是公开会话设置；模型密钥仍仅以引用保存，不进入公开设置和投影。

达到输出长度上限会保留已有输出并显示提示，可直接续聊；截断的工具意图不会执行，回合不能被算作已验证完成。内容过滤、未知终止值和缺少有效终止证据仍按错误处理。

上下文自动整理继续使用唯一的 ContextPipeline。历史裁剪保留有界的早期结论和文件引用，引用作为低信任 assistant 数据，经过原脱敏和注入检查；当前用户权限与工具调用/结果配对不变。原始完整消息和事件不删除。“压缩上下文”会安排下一次请求前整理，正在进行的回合不被打断；界面只在实际准备完成后显示“上下文整理完成”，不把小历史无可裁剪时谎报为节省 token。

插件入口、Agent 预设、内置插件设置、当前版本行、编码状态悬浮窗和空白页口号已在受控衍生组件中移除；上游原件与许可保留。

验收使用真实生产 Web、浏览器、受控本地 HTTP 模型、真实文件和原生事件。安装包 CI 增加同一套八项 PR15 交互检查，任何一项失败均失败，不使用浏览器 RPC mock，不调用付费模型。这些工程验收不能证明真实模型的任务完成质量。
