## 使用

从源码更新后运行 `pnpm build`，重启 Web 进程并刷新页面。输入框左下角的 **＋ → Compact / 压缩** 提交真实的 `/compact` 命令，鼠标和键盘均可使用。为与当前回合的工具结果保持一致，请求在下一次模型采样前执行；界面会明确显示“下一次请求前压缩”。没有可压缩旧历史时只整理上下文，不宣称节省了 token。

日常无需点击：历史占可用消息预算约 85% 且有足够可缩减内容时，默认自动生成交接摘要。系统包装、当前用户/steer 原文和输出空间纳入预算。当前用户文本过大、不可再压缩时明确报限额，不丢弃用户指令。阈值采用 ContextPipeline 的可注入 token 估算器；未知模型仍使用保守预算，设置中应填写模型真实上下文窗口。

摘要采用当前会话模型，禁止工具，输入有限，输出上限 2048 token，时限至多 45 秒且服从本回合剩余时长；请求和用量带 `purpose: compaction`，计入现有预算。合法摘要持久化为不具指令权威的检查点；之后只发送检查点、未覆盖的近期消息和当前人类输入，完整原文继续保存在会话记录中。保留近期完整工具调用/结果，避免压缩后丢失刚执行的动作。

摘要错误、超时、空白、超长、注入或请求工具时采用有限摘录降级，并在 UI 说明；预算耗尽会终止回合。用户取消不会提交检查点或再发编码请求。摘要不显示为聊天答案、计划正文或子任务输出。

压缩期间到达的用户纠正会在编码请求前，经原有 inbox 边界恰好消费一次。它们不被冒充成已经摘要过的内容，下一回合仍保留原文。

## 本轮问题与解决

| 问题 | 解决与验收 |
| --- | --- |
| 旧生产路径主要裁剪历史并保留最多 512 token 摘录，不能生成完整交接摘要 | 参考本地 Codex 的交接提示词、自动阈值、检查点和上下文重新注入。用长历史中的早期事实、新任务原文、跨回合复用及两种持久存储重启验收。 |
| 手动压缩是独立按钮，未使用用户要求的＋入口 | 复用原生命令目录的本地化压缩项，移除重复按钮；实际浏览器测试英文键盘、中文菜单及三种宽度，断言命令 ACK 和持久状态。 |
| 首个语义输出前的流连接重置直接终止回合；普通宿主也未安装可处理它的恢复策略 | 仅对 provider 明确标记可安全重试的瞬时故障，在原控制器内最多尝试三次，显式恢复策略与回合重试预算优先。真实 HTTP 先断开再成功，断言请求一致、真实文件内容及只执行一次工具。 |
| HTTP 200 的 SSE 错误帧被忽略，过载/鉴权/上下文错误变成不明确的 EOF 错误 | 保留结构化、限长、脱敏的错误；无输出的瞬时过载可有限恢复，已确认上下文溢出沿用一次上下文重建。部分文本、思考或工具参数后断连不重放，未知结束原因不冒充完成。 |
| 新检查点集成过程中发现：新会话手动压缩仍追加未进入当前模型视图的旧式 system 摘要，导致已发布聊天前缀变化和 follow 断开 | 新策略使用检查点和既有工作状态持久化，停止追加重复旧式消息；不更改历史日志的解释规则。保留真实中文菜单的失败记录及无工具场景逐事件前缀红/绿复现。此集成缺陷已在推送前修复。 |
