-----------------

(k=QTOKEN). Neither appears anywhere in the emitted plan, the printed
summary, or the saved digest file:

  plan.digest content length = 64 chars, contains only the hex digest
  leak check for 'QTOKEN' / 'tok@' / 'example' in plan.digest: clean

3. Two-phase guards (execute refuses without explicit intent)
------------------------------------------------------------

  execute WITHOUT -AuthorizePaidRun
    -> 'execute requires the explicit -AuthorizePaidRun switch (paid
        authorization is never implicit).'
  execute WITHOUT -PlanDigest
    -> 'execute requires -PlanDigest <64-hex>. This script will not reuse
        the last saved digest automatically.'
  plan missing one budget cap (-MaxLogicalRuns)
    -> 'all four budget caps are required (they are bound into the plan
        digest): missing -MaxLogicalRuns'
  execute with a key present but a WRONG digest (64 x 'f')
    -> 'plan digest mismatch' — refused BEFORE the first provider call

                https://API.Example.Test/v1     (host case)
                https://api.example.test/v1/    (trailing slash)

                http://api.example.test/v1       (scheme)
  a different model (gpt-4o) also changes the digest
