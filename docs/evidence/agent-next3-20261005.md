## 问题与最终行为

[干净基线实际 FIFO 证据](agent-next3-20261005/raw/baseline-fifo/result.json)：沿 production ToolRegistry→ToolOrchestrator→Permission→Sandbox 执行 read_file，60ms 超时约62ms返回，但 native read 与文件锁仍各1；随后同路径调用继续超时，只有350ms外部writer才释放。20ms caller abort 直到约182ms外部writer才结束。普通文件控制通过，起止源码与dist hash相同。

修复保留文件协作锁，用只读非阻塞方式打开路径，再检查**已打开句柄**的 stat.isFile，避免只做path stat后被替换成FIFO。非普通文件不执行内容读取，返回现有 PROCESS_ERROR/非重试失败；普通文件使用 FileHandle.readFile({signal})，在open/stat/read边界检查取消；finally先close，再释放既有锁。正常内容解码、versioned的原始字节sha256/bytes/path和evidence合同保持。

[冻结生产实测](agent-next3-20261005/raw/frozen/read-resource/result.json) 18 场景全部 PASS，源码起止精确等于受测提交、clean、源码/dist指纹相同。native FIFO 不需要外部writer，原路径约 0.901ms、alias约 1.05ms、再次读取约 0.601ms即拒绝；返回时owned descriptor/pending read/file lock均0。native regular read在实际read promise发起后立即caller abort，约 0.570ms 返回 cancelled，无success/evidence，句柄及锁0。此取消探针是受控时序，不能冒称大文件吞吐benchmark。

另包含 Unix socket、directory、missing、BOM/CRLF/Unicode/invalid UTF8/raw-byte hash、regular hardlink/symlink、permission deny、sandbox escape、pre-abort零open、queued reader取消等控制。正式回归另外覆盖open前替换FIFO、open/stat/read边界取消、native stat/read错误和close错误、有效timeout signal及有界250ms清理窗口。

[实际 Harness 搜索→读取→条件编辑](agent-next3-20261005/raw/frozen/read-resource/harness-search-read-edit.json) 使用 production tools 和scripted provider，实际1个turn/4次model请求/3次成功工具：搜索返回值直接作为versioned read路径，从实际tool消息提取sha256交给conditional edit，最终只将A=0改为A=1，保留CRLF和中文。本场景未绕过权限、沙箱或工具编排。

## 实际限制

- 真实模型任务质量、strategy promotion、Windows native运行均NOT_RUN；paid provider calls=0。确定性Harness与loopback HTTP不证明真实模型成功率。
- 本轮只解决read_file；edit_file/checkFileVersion/write_file的特殊文件I/O仍未修复。既有跨进程file-write CAS与一般Sandbox TOCTOU不在范围。
- Node open/stat自身不能强制中断任意慢kernel/network-filesystem操作；O_NONBLOCK防止FIFO等待writer，取消传给regular读取并在异步边界检查。Orchestrator timeout的Promise.race可能先返回，cleanup允许有界异步close窗口，不能声称所有内核I/O瞬时可取消。
- 完整文件读取未增加大小上限，保留versioned完整字节/hash合同；不宣称大文件内存或吞吐优化。设备仅在原权限/沙箱允许时可到达句柄检查，本轮未放宽任何policy来读取设备。
