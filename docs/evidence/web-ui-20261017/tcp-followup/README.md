# 验收中继的分块依赖

0d960c2c 两平台安装 UI 原失败保留，均为 locale 等待 6 秒后仍有实际
settings RPC 处于 sent，后续英文 boot 连锁失败。不能把原 e4a 的本地同包
通过当成该提交 CI 通过，不能仅延长超时。主 CI 仍在原样运行，未取消/重跑。

原透明 TCP 中继在 Transform 回调前逐块等待 350ms；上一个回调完成后才能
处理下一个块，因而实际形成 350*N 的排队，受操作系统 TCP 分块影响。
确定性分块反例原件 tcp-serial-original-red.log：同一到达时刻 40 个字节，
到 350ms 原中继只送出 1 个。修正版到时全部送出，保持顺序和原字节。
真实 TCP 比较 12 块/40ms，原 486ms，新 98ms；原字节完全一致，原量测
以 tcp-fragmentation-wire.json 为准，不把单次时间当作通用性能保证。

中继现在按到达时刻排期；限 1MiB/1024 块待发队列并遵守读/写背压，
关闭时释放计时器，延迟取消后新字节不超车。5 项回归包括 mock-clock
分块、变更延迟、缓冲上限、destroy 和真实 TCP 二进制/EOF；相邻 UI
脚本共 19 项通过，已加入 UI archive CI 前置。产品/6 秒等待预算不变。

初始新测试原型的失败日志也保存：首次文件级 SIGKILL 原因未另行证明；
回显 fixture 改成允许半关闭以等待异步回显，并先核对字节长度；时钟测试
也在读取 data 事件前等待 nextTick。它们没有启动应用，不作为 UI 成败证据。
必须以新固定脚本的完整同包及最终精确 main CI 判断实际验收是否通过。
