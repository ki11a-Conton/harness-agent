## 4. 本场暴露的五处测量缺陷（仅记录，不含修复方案）

### D1 — 作废 arm 的处置规则不自洽：campaign 允许 ≥95%，judge 要求 0 作废

- 事实：campaign 自身合格线是 `completionRatio >= 0.95`（[n7-paired-campaign.mjs:125](../../../scripts/research/agent-next7-20261006/n7-paired-campaign.mjs)），而 judge 的 `full_frozen_grid` 要求 `partial.length === 0`、`infrastructure_qualified` 要求 `status === "COMPLETED"`（[n7-judge-core.mjs:141-147](../../../scripts/research/agent-next7-20261006/n7-judge-core.mjs)）。本场 255/256（99.6%）满足前者、必然不满足后者。
- 后果：**256 个 pair 里任意 1 个 arm 作废即整场不可推断**。512 arms 上按本场观测（1/512）估计，全新一场 main 出现零作废的概率约 37%。
- 且 `--resume` **无法**修复：executor 对已进 journal 的 arm 一律跳过、不看 `valid`（[paired-executor.ts:565-575](../../../packages/evaluation/src/paired-executor.ts)），journal 里 `3ba8b5c0…-baseline.json` 的 `valid=false` 已固化。删除 journal 条目重跑属于销毁证据与按结果挑样本，本场未做。

### D2 — 30 次/run 调用上限边界的 usage 漏记，导致对账门限必失败

- 事实：请求 tape 合计 44,280,105 tokens，arm metrics 合计 44,214,446 tokens，差 **+64,765 input / +894 output**。按 `armRunId` 逐一对账，差异**只**来自 2 个 arm：`3b15d3f7…-candidate`（+32,258/+376）与 `a180156a…-candidate`（+32,507/+518）——两者都恰好 **30 次调用**、`terminationReason=agent_limit`、`grade=unverified_complete`。
- 上限来源：冻结预注册 `budget.maxModelCallsPerRun=30`，封顶在 [n7-paired-campaign.mjs:101](../../../scripts/research/agent-next7-20261006/n7-paired-campaign.mjs) 的 `withModelCallCap`。
- 后果：`reconciliation=false`（[n7-judge-core.mjs:113](../../../scripts/research/agent-next7-20261006/n7-judge-core.mjs)）→ `usage_complete_and_reconciled` 与 `durable_budget_proven` 双 FAIL。**这与 D1 无关**：即使零作废 arm，只要有 1 个 candidate arm 打满 30 calls，这两个门限照样失败。本场该现象发生率 2/512。

### D3 — "模型在工作区外写临时文件"被归为 `infrastructure`，直接作废测量

- 事实：作废 pair `3ba8b5c09a1ea89596252f45`（`n7e-control-01-chunk-tail` rep 2）的 baseline 侧，模型把测试脚本写到工作区外的 `C:\tmp\chunk-test.js`；E1-02 sentinel 记为 `ESCAPE`（`hardBreach=true`），case 结果被标为 `status=error`、`failureCategory="infrastructure"`，于是 `isStrictValidArm` 判 false（[paired-executor.ts:100-105](../../../packages/evaluation/src/paired-executor.ts)）。
- 该 case 是控制用例（要求修 `src/chunk.js`），同一 case 的另外 3 个 repetition baseline 均 `passed`；因此这是**模型偶发路径选择**，不是用例缺陷。
- 后果：一次模型侧的越界写尝试被记为"基础设施故障"并作废整场测量，而不是作为该 arm 的行为结果参与计分（若按 `newSecurityViolationsMax=0` 的既有门限，它本应由 `no_new_security_violations_or_false_completes` 处理）。

### D4 — 归档复算入口 `verify-n7-archive.mjs` 语法错误，从未被执行

- 事实：`scripts/research/agent-next7-20261006/verify-n7-archive.mjs:7-8` 的 `verifyArchive(...)` 调用缺一个右括号；`node --check "scripts/research/agent-next7-20261006/verify-n7-archive.mjs"` 直接报 `SyntaxError: missing ) after argument list`（可复现）。
- 事实：全仓**没有任何测试或其他脚本引用该入口**（在 `*.test.ts` 与 `scripts/` 内检索 `verify-n7-archive` 无命中）→ 验收记录中声明的"归档校验"步骤实际从未运行过。
- 本场处理：**不改冻结脚本**，改用等价的一次性脚本（`.ci/n7/tmp/verify-archive-scratch.mjs`，未跟踪、不进源码指纹）完成校验，输出 `archive verified: main NOT_PROVEN; gates=13; promotion=NOT_ELIGIBLE`——即本目录的 `artifact-index.json`、`RAW-MANIFEST.json` 与现场重算的判定都自洽。
- 注：修复只需补一个 `)`；按操作者指示，本文件只记录缺陷、不改代码，修复留给批准后的计划。

### D5 — 归档判定只能在记录的源码 SHA 上复算：并行提交新增一个 `facts` 字段即导致复算失败

- 事实：归档复算在**记录的 `sourceSha` `7203a01b`** 上通过（输出 `archive verified: main NOT_PROVEN; gates=13; promotion=NOT_ELIGIBLE`）；把本分支变基到并行工作流的 `3ddccafa` 之后，同一复算报 `EXPERIMENT_BINDING_DRIFT`（[campaign-evidence.mjs:17](../../../scripts/research/agent-next7-20261006/campaign-evidence.mjs)）。
- 根因（`facts` 共 77 个键，逐字段对比只有 1 处不同）：并行提交 `b39cb1c9 fix(evaluation): stabilize active arm identity and checkpoint interrupted campaigns` 给 `facts` **新增了一个格式标记字段** `armDigestFormat: "active-mechanisms-v2"`；`planDigest`、`candidates`、`armDigests`、`runtimeConfigHashes`、`caseFingerprints` **全部逐字节未变**。
- 后果：`facts` 是执行身份的一部分（`identityOk` 断言 `stable(header.facts) === stable(facts)`），因此**任何后续源码改动都可能让旧归档无法在原地复算**；正确做法是固定到记录的 `sourceSha`（本场 `7203a01b`），而现有入口（含 D4 那个坏脚本）都没有这一步。
- 本场的替代校验（兼容口径：仍走全部冻结代码路径——`verifyCampaignRaw` / `verifyIndex` / `recoverPairs` / `conditionProbe` / `judgeData`——只把 `facts` 取自已归档的 `campaign-header.json`，而不是按当前源码重算）：`raw-manifest/index OK`、`recorded facts vs binding OK`、**重算判定与归档 `judge-result.json` 逐字段相同**（`recomputed judgment identical to archive: true`）。→ **归档与原始字节自洽；不能原地复算只是源码漂移，不是归档损坏。**
