## 3. 正面回答 D3 的两个问题

**Q1：`denominator >= 20` 与既有 `minRepetitionsPerTask: 3` / `belowStratumMinimum` 是否冲突？**
**答：不冲突，但是两条不同的轨道——而且当前只接通了一条。**

- 既有机制：`SpecMetricsOptions.minStratumRuns`（`harness-metrics.ts:382`，默认 **1**，`:889`）决定 `belowStratumMinimum`，作用于**整个 strata 的每个指标**（`:1167-1171`）。它与"单个指标的分母下限"**不是同一个量**。
- 门禁侧：`thresholdGate`（`:254-310`）只检查 `denominator > 0`（`:292`），**不接收任何最小样本参数**；`GateContext`（`:238-242`）只有 `requireRegressionZero` / `strictTaskSuccess` / `minRepetitions` 三个字段，**没有安全类最小样本**。
- 因此 D3 的"分母 ≥ 20"是**新增口径，不是仓库现状**：它既不与 `minStratumRuns` 冲突（不同粒度），也无法被今天的门禁表达（**缺参数**）。**请按"建议"标注，不要写成"仓库现状"。**
- 我的评测视角意见：`minStratumRuns` 默认 **1** 意味着**默认配置下 strata 永远不触发小样本标注**——这是一条比 D3 的 n=20 更基础的口径缺口：**默认值让该机制形同虚设**。

**Q2：`NO_ATTACK_ATTEMPT` 的第三态？（我的 M6 二分法）**
**答：D3 对，我补第三态，且它必须是"不可作通过证据"的显式状态。**

| 态 | 含义 | 计入分子？ | 计入分母？ |
| --- | --- | --- | --- |
| `MEASURED` | 观测到有效事态可用于判定 | 视结果 | 是 |
| `INSUFFICIENT_SAMPLE` | 缺数据（`value: null`） | 否 | **否** |
| `OBSERVED_NO_EVENT`（新） | **观测到了、事实是"没发生"**，但不能作通过证据 | **否** | **是** |

理由：`INSUFFICIENT_SAMPLE` 是"我不知道"，`OBSERVED_NO_EVENT` 是"我知道没发生"。**把后者塞进分子就是 M1 的残余风险（1 个样本宣称 100%）；把它塞进 `INSUFFICIENT_SAMPLE` 又会丢掉一个真实观测。** 本仓库对应的现成形态：`harness-metrics.ts:1100-1112` 把"无事件轨迹"记为 **真实 0**（注释明写 "is a REAL 0"）并**单独**累计 `traceLegacy`——**这正是第三态的正确实现**，可以直接照搬到安全侧。→ **本仓库有正例，不必新造。**

- **拒绝 D5 把 M9 机制③并入 M5**：D5 说"改小历史通过集"是 M5 特例，会让 M9 显得虚强。**我部分接受**：③ 与 M5 **同源**，但**作用不同**——M5 是"分母变小 ⇒ 指标变好（假高）"，机制③ 是"分母变小 ⇒ 回归数变 0 ⇒ **门禁放行**"。**一个污染读数，一个污染决策**，保留为 M9 的机制但**显式标注"系 M5 在回归维度上的实例"**。
- **接受 D5 的"成本-回归联合门槛"，但改口径**：D5 提"回归为 0 但成本升超 X% 不该通过"。从测量视角这**不是**一条独立门槛，而是**违反成本口径的可比性**：成本与通过率在 `$/passed task` 下是**同一个分数的两面**（D5 的 H4 说得对）。**正确形态**：成本门限应写成"**在通过率不下降的前提下**"的边际成本，而不是与回归数做联合判定——否则两个不同起点的版本会被同一个 X% 误杀。

## 5. 我对 D1 提出的 `isHardLimit` 死代码问题的裁定（D1 明确交我判）

**裁定：它是过时契约，不是死代码的"无害残留"——作为门禁输入时必须视为不可信。**

- 事实（我实测）：`run-budget.ts:136-139` `isHardLimit` 返回 `breach.limit !== "maxEstimatedCostUsd" && breach.limit !== "maxTurns"`，即把**成本与 turn 上限排除在硬限之外**；`:141` 只有 `void isHardLimit` 消 lint；**全仓 `packages/**/src/*.ts` + `apps/**/src/*.ts` 零调用点**（仅 `r92-authorization.ts` 的**文本**引用它，且是把它当作"不能终止 run"的证据）。
- 与之**直接矛盾**的实现：`runtime.ts:1196-1203` 在 `onModelUsage` 报 `costBreach` 时 `emit("run.limit_reached")` 并 `finishTurn(..., "RESOURCE_LIMIT", "agent_limit")`——**成本触限确实终止了 turn**。
- **评测口径的含义（这是我要回答 D1 的部分）**：`r92-authorization.ts` 说的"cost 维度是 preflight-only、非硬限"针对的是**agent-run 层的授权判断**，而 `runtime.ts` 说的是**turn 层**。两者**层级不同**，因此可以同时为真——**但函数名与签名不表达层级**，而当前**零调用**说明它没有活的判定作用。
- **门禁处方**：任何声称"成本/轮次有硬上限"的门限，**不得引用 `isHardLimit`**；必须以 `runtime.ts:1196-1203` 的 `run.limit_reached` + `terminationReason === "agent_limit"` 为判据。同时 D1 的 resume 发现（§2）意味着**即使这个终止是对的，累计值本身在 resume 后偏小**——两个缺陷叠加会让 `$/passed task` 与 `tokens_within_110pct` 双双失真。
- **我无法判定的部分（如实说）**：它是"过时契约"还是"预留 API"，**从零调用点无法区分**；但从门禁角度，**这两者的处置相同：不得作为判据**。

## 6. 对 D1 转来的 D3 悬置问题（`denominator >= 20`）的裁决 —— **我不认 20**

**事实核对（我实测）**：`harness-metrics.ts:889` `minStratumRuns = Math.max(0, Math.floor(options.minStratumRuns ?? 1))` — **默认 1**（注释 `:376-381` 同）。故 D1 猜的"默认 0 导致防线恒空转"**不成立**；但**真实缺陷更微妙**：默认 1 ⇒ 只有**空 strata** 被标注，**任何非空 strata（含 n=1）都判 `MEASURED`** → n=1、0 failures、`denominator > 0` ⇒ **PASS**。**D1 的 Q1 前提（"1 个样本到不了 `:292`"）只在调用方显式传 `minStratumRuns >= 2` 时成立，默认路径不传。**

1. **不接受裸的 `20`**：无统计依据。正确形态是**由要宣称的置信水平反推**——零失败下宣称"违规率 < 1%"到 95% 置信需 `0.99^n <= 0.05` ⇒ **n ≈ 299**；而 **n=20 的零失败 95% 单侧上界 ≈ 14%**（D3 自己的 3/n 逻辑），**只支持"违规率 < 14%"**，与"已验证 100%"不匹配。→ 应写成 `ceil(ln(1-置信)/ln(1-目标违规率))` 并标注参数，**不出现裸整数**。
2. **`minStratumRuns` 不是该下界的载体**：它是 **strata 级**（作用"整个 strata 的每个指标"，`:1167-1171`），D3 的 20 是**单指标级**；把 `minStratumRuns` 调到 20 会连带把同 strata 的成功率/延迟/成本全打成 `INSUFFICIENT_SAMPLE`。
3. **落点**：给 `thresholdGate`（`harness-conformance-gate.ts:254-310`）加"最小分母下界"参数，语义 `0 < denominator < n_min ⇒ INSUFFICIENT_SAMPLE`，**交既有 fail-closed 执行**，不新增并列 hard gate（同意 D1"并列门限会让'哪些规则生效'本身不可判"）。
4. **D3 的"每类越权面 ≥5"我认**，但它是**分层充分性**要求，落点是**安全轴上的 `minStratumRuns`**（per-strata，正是该字段本意用法）。故 D3 两条建议落点不同，不应合并。

## 8. 本轮新增的一条主张（由三方压力逼出）

### M12（双向变异）门禁变更必须配"反向变异"证据，否则"改回去"无法被检出·**新增**

- **主张**：正向变异（关掉机制 → 用例变红）只证明**断言非空洞**；还必须有一条**反向变异**（把机制改回**曾经的错误形态** → 用例变红），才能证明**已发生过的错误不会复发**。
- **为什么**：N7 的 D3 事故（`ESCAPE` 的 `detail` 是 `"wrote outside workspace (E1-02): C:\tmp\chunk-test.js"`，而**同一记录 `escapedPaths` 为空**、该文件复核时不存在）是**事实方向差**，比 M3 的数值口径差更严重。若测试集里没有"把 `escapedPaths` 从成功副作用改回请求路径派生 → 必须变红"这一条，**该错误在当前测试集上不可检出**——它是一条**已经发生过的真实事故路径上缺反例**。
- **可观测判据**：`EVIDENCE-INDEX.md` §4 的 7 组安全变异清单我逐条核对，**确无此条**（D3 问，我确认）。→ **本仓库缺失，明说没有。**
- **失败模式**：测试全绿，而库里躺着一个已被证伪的判定路径。
- **最容易被伪造**：只做正向变异就宣称"断言非空洞"，把"非空洞"偷换成"不会退化"。
