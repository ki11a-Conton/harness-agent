## 3. 正面回答 D3 的两个问题

**Q1：`denominator >= 20` 与既有 `minRepetitionsPerTask: 3` / `belowStratumMinimum` 冲突吗？**
**答：不冲突，是两条不同轨道，而当前只接通了一条。**
- 既有：`minStratumRuns`（`harness-metrics.ts:382`，默认 **1**，`:889`）决定 `belowStratumMinimum`，作用于**整个 strata 的每个指标**（`:1167-1171`）——与"单指标分母下限"**不是同一个量**。
- 门禁侧：`thresholdGate`（`:254-310`）只检查 `denominator > 0`（`:292`），**不接收最小样本参数**；`GateContext`（`:238-242`）只有 `requireRegressionZero`/`strictTaskSuccess`/`minRepetitions`。
- 故"分母 ≥ 20"是**新增口径，不是仓库现状**：不与 `minStratumRuns` 冲突（不同粒度），但今天的门禁**无法表达它（缺参数）**。**请按"建议"标注。**
- **我补一条更基础的缺口**：`minStratumRuns` 默认 **1** ⇒ **默认配置下小样本标注永不触发**——默认值让该机制形同虚设。

**Q2：`NO_ATTACK_ATTEMPT` 需要第三态吗？**
**答：D3 对，我补，且它必须是"不可作通过证据"的显式状态。**

| 态 | 含义 | 进分子？ | 进分母？ |
| --- | --- | --- | --- |
| `MEASURED` | 观测到有效事态可用于判定 | 视结果 | 是 |
| `INSUFFICIENT_SAMPLE` | 缺数据（`value: null`） | 否 | **否** |
| `OBSERVED_NO_EVENT`（新） | **观测到了、事实是"没发生"**，但不可作通过证据 | **否** | **是** |
理由：前者是"我不知道"，后者是"我知道没发生"。**塞进分子 ⇒ M1 的残余风险（1 个样本宣称 100%）；塞进 `INSUFFICIENT_SAMPLE` ⇒ 丢掉一个真实观测。** 现成正例：`harness-metrics.ts:1100-1112` 把"无事件轨迹"记为 **真实 0**（注释 "is a REAL 0"）并**单独**累计 `traceLegacy` —— **第三态的正确实现，照搬到安全侧即可，不必新造。**

- **拒绝 D5 把 M9 机制③并入 M5**：③ 与 M5 **同源**，但**作用不同**——M5 是"分母变小 ⇒ 指标变好（假高）"，③ 是"分母变小 ⇒ 回归数变 0 ⇒ **门禁放行**"。**一个污染读数，一个污染决策**，故保留为 M9 的机制但**标注"系 M5 在回归维度上的实例"**。
- **接受 D5 的"成本-回归联合门槛"，但改口径**：从测量视角这**不是**独立门槛，而是**违反成本口径的可比性**——成本与通过率在 `$/passed task` 下是**同一分数的两面**（D5 的 H4 对）。**正确形态**：写成"**通过率不下降前提下**"的边际成本，不与回归数做联合判定，否则不同起点的版本会被同一个 X% 误杀。

## 5. 我对 D1 提出的 `isHardLimit` 问题的裁定（D1 交我判）

**裁定：作为门禁输入时必须视为不可信。** 事实（我实测）：`run-budget.ts:136-139` `isHardLimit` 返回 `breach.limit !== "maxEstimatedCostUsd" && breach.limit !== "maxTurns"`，即把**成本与 turn 上限排除在硬限之外**；`:141` 只有 `void isHardLimit` 消 lint；**全仓零调用点**（仅 `r92-authorization.ts` 的**文本**引用，且是把它当作"不能终止 run"的证据）。

- **与之直接矛盾**：`runtime.ts:1196-1203` 在 `onModelUsage` 报 `costBreach` 时 `emit("run.limit_reached")` 并 `finishTurn(..., "RESOURCE_LIMIT", "agent_limit")`——**成本触限确实终止了 turn**。
- **调和**：`r92` 的"cost 是 preflight-only、非硬限"针对**授权层**，`runtime.ts` 说的是 **turn 层**，层级不同可同时为真——**但函数名与签名不表达层级**，零调用说明它无活的判定作用。**处方：任何"成本/轮次有硬上限"的门限不得引用 `isHardLimit`**，须以 `run.limit_reached` + `terminationReason === "agent_limit"` 为判据。叠加 §2 的 resume 缺陷，`$/passed task` 与 `tokens_within_110pct` 会双双失真。
- **无法判定的部分（如实说）**：它是"过时契约"还是"预留 API"，**从零调用点无法区分**；但从门禁角度两者处置相同：**不得作为判据**。

## 6. 对 D3 悬置问题（`denominator >= 20`）的裁决 —— **我不认 20**

**事实核对（我实测）**：`harness-metrics.ts:889` `minStratumRuns = Math.max(0, Math.floor(options.minStratumRuns ?? 1))` — **默认 1**。故 D1 猜的"默认 0 导致防线恒空转"**不成立**；但**真实缺陷更微妙**：默认 1 ⇒ 只有**空 strata** 被标注，**任何非空 strata（含 n=1）都判 `MEASURED`** ⇒ n=1、0 failures、`denominator > 0` ⇒ **PASS**。**D1 的 Q1 前提只在调用方显式传 `minStratumRuns >= 2` 时成立。**

1. **不接受裸的 `20`**：无统计依据。应由**要宣称的置信水平反推**——零失败下宣称"违规率 < 1%"到 95% 置信需 `0.99^n <= 0.05` ⇒ **n ≈ 299**；**n=20 的零失败 95% 单侧上界 ≈ 14%**，**只支持"违规率 < 14%"**，与"已验证 100%"不匹配。→ 写成 `ceil(ln(1-置信)/ln(1-目标违规率))` 并标注参数。
2. **`minStratumRuns` 不是该下界的载体**：它是 **strata 级**（`:1167-1171`），20 是**单指标级**；调到 20 会连带把同 strata 的成功率/延迟/成本全打成 `INSUFFICIENT_SAMPLE`。
3. **落点**：给 `thresholdGate`（`harness-conformance-gate.ts:254-310`）加"最小分母下界"参数，语义 `0 < denominator < n_min ⇒ INSUFFICIENT_SAMPLE`，**交既有 fail-closed 执行**，不新增并列 hard gate（同意 D1"并列门限会让'哪些规则生效'本身不可判"）。
4. **D3 的"每类越权面 ≥5"我认**，但它是**分层充分性**要求，落点是**安全轴上的 `minStratumRuns`**（per-strata）。故 D3 两条建议落点不同，不应合并。

## 8. 新增主张 M12：门禁变更必须配"反向变异"证据
- **主张**：正向变异（关掉机制 → 用例变红）只证明**断言非空洞**；还必须有一条**反向变异**（把机制改回**曾经的错误形态** → 用例变红），才能证明**已发生过的错误不会复发**。
- **为什么**：N7 的 D3 事故（`ESCAPE` 的 `detail` 写 `"wrote outside workspace (E1-02): C:\tmp\chunk-test.js"`，而**同一记录 `escapedPaths` 为空**、该文件复核时不存在）是**事实方向差**，比 M3 的数值口径差更严重。缺这一条 ⇒ **该错误在当前测试集上不可检出**。
- **可观测判据**：`EVIDENCE-INDEX.md` §4 的 7 组安全变异清单我逐条核对，**确无此条**。→ **本仓库缺失，明说没有。**
- **失败模式 / 最易伪造**：测试全绿而库里躺着一条已被证伪的判定路径；只做正向变异就宣称"断言非空洞"，把"非空洞"偷换成"不会退化"。
