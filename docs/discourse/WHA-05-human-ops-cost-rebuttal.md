## 1. 我接受的反对（3 条，均已就地改正，原句保留标注）

**1.1 D1 反对我把 `estimated_cost` 列入 H1 的判据 → 接受，且这是我的自我矛盾。**
D1 指出该字段在 `run-budget.ts:74-79` 累加的是**调用方传入的** `costUsd`，而 `metrics.ts:117-137` 在无显式 cost 时**套默认费率估算**。我复核确认 `:77` 为 `this.estimatedCostUsd += costUsd;`。→ 一个字段名承载"账单/估算/声明上界"三种语义，**而我 H5 恰恰主张成本必须带口径标签**。已从 H1 删除裸 `estimated_cost`，改为 `estimated_cost(caveat: 三选一)`，并在 H1 原样记录"此矛盾由他人复核发现"。**教训适用全讨论：判据若依赖一个语义重载的字段，它就不可判。**

**1.2 D1 反对 H3 的判据"审批请求数 == 不可逆动作数" → 接受，原式不可判。**
D1 的理由：审批请求来自策略引擎，而"不可逆"是工具语义（`ToolSemantics.sideEffectScope`），两者**没有共同 ground truth**，无法机器检查。已改为事件流上可判定的形式：*每个 `sideEffectScope != "none"` 且未被策略预先 allow 的调用，必须存在同 `toolCallId` 的审批记录，或一条 `security.permission_denied`*。**这条修订对我是净收益：它把一条我写得很顺但不可判的句子换成了可判据。**

**1.3 D2 反对 H2 的判据未经执行 → 接受，这是我的方法论错误。**
我 H2 的判据写"跑一次带人类审批的 run，`total_human_interventions` 应 >0"，但**我从未跑过**（本视角 0 付费调用，且需真实 provider）。D2 指出：**一条未执行的可观测判据，正是我 H6 反对的形态。** 已在 H2 标注"静态推断，未运行时验证"，并把已执行的**静态检索**单列：`paired-executor.ts` 仅 `:193` 一处 `human_interventions: 0`；全仓 `packages/**/src`、`apps/**/src` 检索 `human_interventions:\s*[1-9]` **除 `*.test.ts` 外零命中**。→ **H2 的证据强度从"实测"降级为"静态"，我如实标注。**

## 2. 我采纳的反驳（2 条：让主张更强，不是让步）
